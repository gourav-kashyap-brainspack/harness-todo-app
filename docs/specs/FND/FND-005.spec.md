# FND-005 — Shared UI primitives: empty state · loader · responsive · a11y

## Goal
Build the reusable presentational primitives every feature reuses, so no module reinvents them: a themed **EmptyState** (F-030), a **LoadingIndicator** (F-032), a **responsive layout** container/helpers (F-046), and the **accessibility-label conventions** baked into the primitives (F-047). These are the anchor `src/components/ui` components — the code-reviewer blocks any feature re-implementing them.

## Context links
- Source feature(s): F-030 (Empty State), F-032 (Loading Indicator), F-046 (Responsive Layout), F-047 (Accessibility Labels) · `docs/requirements/features.csv`
- Design system: `docs/context/design-system.md` (tokens from FND-002)
- Conventions: `docs/context/conventions.md` (components in `src/components/ui`; a11y labels on every interactive element)
- Graphify: `graphify query "empty state"` (empty until built)

## Functional requirements
- **FR1 — `EmptyState` (F-030):** props `{ title, message?, icon?, action? }`. Themed via tokens; centered; icon from the vector-icon set. Used by "no tasks", "no completed tasks", and (config) "no search results" (F-031 in ORG reuses this — do not fork it). Friendly copy per the PRD §7.8.
- **FR2 — `LoadingIndicator` (F-032):** a themed spinner/skeleton wrapper, props `{ label? }`, with `accessibilityRole` + a screen-reader label ("Loading…"). Used while local data hydrates and on pull-to-refresh (TSK F-042 reuses it).
- **FR3 — Responsive layout (F-046):** a `Screen`/`Container` primitive that applies SafeArea insets + max-width/gutter behavior and adapts to different mobile widths & orientations using NativeWind responsive utilities + `useWindowDimensions`. Establishes the responsive convention (multiple mobile screen sizes per PRD §11 Usability). No fixed pixel widths that break on small devices.
- **FR4 — Accessibility conventions (F-047):** every interactive primitive exposes `accessibilityLabel` + `accessibilityRole`, minimum touch target ≥44pt/48dp, and supports Dynamic Type / `fontScale`. Document the convention in `design-system.md` so feature builders apply it uniformly; these primitives are the reference implementation.
- **FR5 — Barrel export** from `src/components/ui` so features import `@/components/ui`.

## Non-functional requirements
- **Accessibility (F-047):** the primitives are the a11y reference — correct roles/labels, target sizes, contrast (both themes), never color-alone for state.
- **Performance:** primitives are lightweight, memo-friendly; no layout thrash on resize.
- **Maintainability:** one implementation each; features reuse (Tier-1) — reinventing is a `[blocking]` review finding.

## Platform divergence (iOS / Android)
- SafeArea insets differ (notch/home-indicator vs nav bar) — the `Screen`/`Container` handles both via `react-native-safe-area-context`.
- Shadow (iOS) vs elevation (Android) if the primitives use raised surfaces — use a themed helper, not per-OS hardcode.

## Offline / degraded network
- Fully offline — presentational only. The EmptyState/Loader are what feature surfaces show while local data loads (no network states).

## Accessibility
