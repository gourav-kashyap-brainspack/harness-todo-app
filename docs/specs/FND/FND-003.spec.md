# FND-003 — Navigation shell (bottom-tabs + native-stack)

## Goal
Build the app's navigation tree: a **bottom-tab navigator** with two tabs — **Home** and **Profile** (F-039) — wrapped in a **root native-stack** that also hosts the Splash and Profile-Setup screens and the pushed task screens (Add Task, Edit Task, Task Detail — presented as **pushed stack screens** per the resolved decision). Establishes the **Tier-1 typed-navigation pattern** (route param types) that PRO/TSK consume. Screens are placeholder stubs here; feature modules fill them in.

## Context links
- Source feature(s): F-039 (Bottom Tab Navigation). Related nav features live in TSK: F-040 (→ detail), F-041 (→ edit) — this task provides the routes they navigate to.
- Conventions: `docs/context/conventions.md` (navigators in `src/app/navigation`; typed params)
- Architecture: `docs/context/architecture.md`
- Graphify: `graphify query "navigation"` (empty until built)

## Functional requirements
- **FR1 — Root native-stack** (`RootStack`) in `src/app/navigation`:
  - `Splash` (initial route — hands off to FND-004's bootstrap logic)
  - `ProfileSetup` (shown on first launch — placeholder here; built in PRO)
  - `Tabs` (the bottom-tab navigator)
  - `AddTask`, `EditTask`, `TaskDetail` (pushed screens — placeholders; built in TSK)
- **FR2 — Bottom-tab navigator** (`Tabs`) with exactly two tabs: **Home** and **Profile**, each a placeholder screen. Tab bar uses `react-native-vector-icons` glyphs + labels, themed via tokens (FND-002), respecting safe-area insets.
- **FR3 — Typed routes:** a `RootStackParamList` + `TabParamList` (TS types in `src/app/navigation`), typed `useNavigation`/`useRoute` helpers, and typed route params for the task screens (`TaskDetail: { taskId: string }`, `EditTask: { taskId: string }`, `AddTask: undefined`). This is the anchor **navigation param typing** pattern.
- **FR4 — Navigation theming:** the `NavigationContainer` theme derives from the active app theme (FND-002) so headers/backgrounds/borders match light/dark; status-bar style flips with the resolved scheme.
- **FR5 — Header config:** native-stack headers with back navigation for pushed screens; tab screens headerless or with a themed header per design. Titles/labels are real (Home, Profile, Add Task, Edit Task, Task Details).
- **FR6 — Mount in `AppProviders`:** `NavigationContainer` mounts inside the providers from FND-001/002 (SafeArea, Theme). `App.tsx` → providers → navigation.
- **FR7 — Accessibility:** tab buttons carry an `accessibilityLabel` (Maestro anchors on visible text/`accessibilityLabel`, NOT `testID` — per conventions §E2E selectors). Use stable visible tab labels (`Home`, `Profile`).

## Non-functional requirements
- **Performance:** `react-native-screens` enabled (native screen optimization); no unnecessary re-renders of the tab bar on navigation.
- **Accessibility:** tab targets ≥ 48dp; labels present for screen readers; regex-anchorable text for E2E.

## UI / design notes

## Platform divergence (iOS / Android)
- Safe-area handling for the tab bar (home-indicator inset on iOS; nav-bar on Android). Back gesture: native-stack gives iOS swipe-back + Android hardware-back automatically — verify hardware back on Android pops the stack correctly.
- Header height / status-bar treatment differs per OS — rely on native-stack defaults + safe-area.

## Offline / degraded network
- Fully offline — navigation has no network dependency.

## Accessibility

## Deep links & native permissions
- **No deep links in MVP** (none in scope). Structure the `RootStack` so a linking config could be added later, but do not wire one now. No permissions.

## Performance budget
