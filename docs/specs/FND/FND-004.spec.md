# FND-004 — App bootstrap: splash · first-launch · offline shell

## Goal
Wire the app's boot sequence: a **splash screen** while local data loads (F-043), **first-launch detection** that routes a brand-new user to Profile Setup vs. a returning user to Home (F-044), and confirmation that the whole app **operates fully offline** (F-048). This closes the FND critical path — after it, the shell boots, gates first-launch correctly, and needs no network.

## Context links
- Source feature(s): F-043 (Splash), F-044 (First Launch Detection), F-048 (Offline Operation) · `docs/requirements/features.csv`
- User journey: `docs/requirements/prd.md` §6/§10 (Splash → Profile Setup [first launch] → Home)
- Resolved decision: **FND installs MMKV + reads a minimal `hasLaunched` flag**; STG later builds the typed storage service.
- Graphify: `graphify query "bootstrap"` (empty until built)

## Functional requirements
- **FR1 — Native splash (react-native-bootsplash):** configured for Android + iOS, showing the app logo/brand on cold start, hidden by JS once the boot sequence is ready. Themed background (respects the resolved scheme where the platform allows).
- **FR2 — JS bootstrap sequence** (a `Splash`/`Bootstrap` screen or a boot hook): on mount, (a) restore theme mode (FND-002), (b) read the **first-launch flag** from MMKV, (c) hide the native splash, (d) navigate to the correct entry route. Must complete well under the **3s startup NFR** (PRD §11).
- **FR3 — First-launch detection (F-044):** read a raw MMKV boolean `hasLaunched`. If **absent/false** → route to `ProfileSetup` (placeholder now; PRO builds it) and set `hasLaunched=true` once setup completes (PRO owns the "completed" write; FND provides the flag + the routing seam). If **true** → route to `Tabs` (Home). Document the seam so PRO can refine it to "profile exists?" without a second source of truth.
- **FR4 — Offline shell (F-048):** the entire boot path has **zero network calls**; `react-query` is not mounted; no provider awaits connectivity. Prove the app launches and is fully usable in airplane mode. (No NetInfo gating — the app is local-only.)
- **FR5 — Status bar + safe area at boot:** status-bar style set from the resolved theme scheme; SafeArea respected on the splash/first screen.
- **FR6 — Corrupted-flag resilience (light):** if the `hasLaunched` read throws or returns a non-boolean, default safely to **first-launch = true routing to ProfileSetup** (never crash on boot). Full corrupted-data recovery for domain data is STG's F-038; this is just the boot flag's safety.

## Non-functional requirements
- **Performance:** cold start to interactive **< 3s** (PRD §11) on a mid-range device; splash hidden as soon as boot state is resolved (no artificial delay).
- **Reliability:** boot never crashes on a bad/missing flag (F-044/§11 "recover from invalid data").
- **Offline:** 100% functional with no connectivity (F-048).
