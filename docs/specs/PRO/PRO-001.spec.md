# PRO-001 — Profile store + RHF/Zod form pattern + Profile Setup

## Goal
Deliver the app's first real form flow: the **Profile Setup screen** shown on first launch (F-001, mandatory name **and** email per OQ-2), backed by a **profile Zustand store** that hydrates from the STG `profileRepository`, and the **RHF + Zod form pattern** (with inline validation errors, F-033) that this task **anchors** for the whole app (TSK reuses it). On a valid submit it persists the profile and calls `setHasLaunched()` — the single seam that lets the app leave ProfileSetup for Home (STG coherence gap e). This is the PRO anchor.

## Context links
- Source feature(s): F-001 (Create User Profile), F-033 (Display Validation Errors) · `docs/requirements/REQUIREMENTS.md`
- STG seam: `mobile/src/core/services/profileRepository.ts` (`getProfile`/`saveProfile`/`clearProfile`) + `core/types/profile.ts` (`profileSchema`, `Profile`). Hydration helper `createPersistedValue` in `core/services/storage.ts`.
- FND seam: `mobile/src/core/store/launchStore.ts` (`useLaunchStore().setHasLaunched`), the `ProfileSetup` route + placeholder in `src/app/navigation/screens.tsx`, the `Screen`/`EmptyState`/`LoadingIndicator` primitives (`@/components/ui`), theme tokens.
- Conventions: `docs/context/conventions.md` (RHF+Zod at the form boundary; features in `src/features/**`; no direct MMKV).
- **STG coherence gaps (from `docs/graph/coherence/STG.md`), MUST honor:** (e) PRO calls `setHasLaunched()` ONLY when setup genuinely completes — no second "profile exists" flag; (f) validate at the form boundary (RHF + `zodResolver`) so `saveProfile`'s throw-on-invalid path is NEVER user-reachable.

## Functional requirements
- **FR1 — Profile store** (`src/features/profile/store` — feature state): a Zustand store holding `profile: Profile | null` + actions (`setProfile(p)`, `clearProfile()`), **hydrated once at init from `profileRepository.getProfile()`** (via the STG hydration recipe / a synchronous seed — follow the `createPersistedValue` pattern). Writes go through `profileRepository.saveProfile` (never direct MMKV). This store is the single source of profile state PRO-002/PRO-003 consume.
- **FR2 — RHF + Zod form pattern (ANCHOR, F-033):** a form built with `react-hook-form` + `@hookform/resolvers/zod` using **`profileSchema`** as the resolver. Inline field-level validation errors surfaced under each field (F-033) from RHF's `formState.errors`. This is the Tier-1 form pattern the librarian promotes; keep it exemplary + reusable (a small `FormField`/error-text approach TSK can copy). Validation runs at the boundary (gap f) → `saveProfile` only ever receives a schema-valid `Profile`.
- **FR3 — Profile Setup screen** (`src/features/profile/screens/ProfileSetupScreen`, replacing the FND placeholder on the `ProfileSetup` route): fields **Name** (required) + **Email** (required, valid email). **Mandatory — no skip** (OQ-2). Uses the `Screen` primitive + theme tokens. Submit is disabled/guarded until valid; on submit → `saveProfile` + `setProfile` + **`setHasLaunched()`** → navigation proceeds to `Tabs` (Home). Photo is NOT part of setup (optional, added in PRO-003).
- **FR4 — First-launch gating (gap e / coherence check 3):** the app's boot routing (FND `BootstrapScreen`) already routes first-launch → `ProfileSetup`. This task makes **completing setup** call `setHasLaunched()` — the ONLY writer of that flag — so a returning launch goes to Home. Do NOT introduce a separate "profile exists" flag; `app.hasLaunched` stays the single source of truth. Edge: force-quit mid-setup → next launch still ProfileSetup (flag not yet set) — correct.
- **FR5 — Duplicate-submit guard:** prevent double submission (rapid taps) creating a race (a lightweight `isSubmitting` guard; aligns with F-035's spirit though F-035 is TSK's). Submit is idempotent.

## Non-functional requirements
- **Accessibility (F-033 + FND a11y baseline):** every input has an `accessibilityLabel`; validation errors are associated/announced (accessibilityLiveRegion or role) so a screen-reader user hears them; submit button labeled; ≥44/48dp targets; fontScale-safe. Visible field text anchors for Maestro.
- **Reliability:** validation prevents invalid persistence (gap f). Keyboard handling (KeyboardAvoidingView / avoid the submit button being covered).
- **Performance:** synchronous store hydration (one repo read) at boot; no jank.
