# PRO-002 — Profile view + edit screen (+ theme toggle)

## Goal
Build the **Profile tab** screen: **view** the saved profile (F-005 — name, email, photo placeholder) and **edit** it (F-002 — both name and email freely editable, same validation as setup). Also mount the **theme toggle** (light / dark / system) here — the control FND-002 deliberately deferred to the Profile screen, completing the dark-mode feature (OQ-10). Reuses the PRO-001 profile store + RHF/Zod form pattern.

## Context links
- Source feature(s): F-005 (View User Profile), F-002 (Edit User Profile) · `docs/requirements/REQUIREMENTS.md`
- Depends on: PRO-001 (profile store, RHF+Zod form pattern, `profileRepository` wiring).
- FND seam: `Profile` route + placeholder (`src/app/navigation/screens.tsx`), `themeStore` (`useThemeStore`/`useTheme` — `mode`, `setMode`), `Screen`/UI primitives, tokens.
- FND-002 note (design-system.md / spec): the theme toggle mechanism (`setMode`, `mode: system|light|dark`) exists; **its UI was deferred to the Profile screen** — this task builds it.

## Functional requirements
- **FR1 — Profile view (F-005):** the `Profile` tab screen displays the saved profile from the PRO-001 store — name, email, and the photo (avatar placeholder until PRO-003 adds the real photo; show initials/placeholder avatar). Clean read layout using the `Screen` primitive + tokens. If somehow no profile (shouldn't happen post-setup), show a safe empty/`EmptyState` with a prompt to set it up.
- **FR2 — Profile edit (F-002):** an edit affordance (edit button → edit mode or an Edit screen) using the **same RHF + Zod form pattern from PRO-001** (`zodResolver(profileSchema)`, inline errors F-033). **Both name and email are editable** (resolved decision); both required + valid on save. On save → `profileRepository.saveProfile` + update the store; cancel discards. Validation at the boundary (gap f) — invalid never reaches `saveProfile`.
- **FR3 — Theme toggle:** a control (segmented / switch / options) for **System · Light · Dark** wired to `themeStore.setMode`; reflects the current `mode`; the change is instant + persisted (themeStore already persists to MMKV). Lives on the Profile screen. Labeled + accessible.
- **FR4 — No duplicate state:** the screen reads profile from the single PRO-001 store; theme from the single `themeStore`. No copied/duplicated profile or theme state (coherence).

## Non-functional requirements
- **Accessibility:** view text is readable (contrast both themes); edit inputs labeled + errors announced (F-033); the theme toggle has clear labels + `accessibilityRole` (radio/switch) + announces selection; ≥48dp; fontScale-safe.
- **Performance:** instant theme switch (no tree remount — FND-002 guarantee); edit save is a local write.

## UI / design notes

Reuse the PRO-001 form-field/error pattern for edit. Distinctive, not default-RN-slop (banned-defaults list).
- Avatar placeholder (initials or a Feather `user` glyph in a `primary/10` chip — consistent with the EmptyState icon treatment) until PRO-003.

- edit: opens with current values; `zodResolver` rejects empty name / invalid email (F-033); valid save calls `saveProfile` + updates store; cancel discards; invalid never calls `saveProfile` (gap f).
