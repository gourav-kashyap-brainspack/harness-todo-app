# ORG-001 — Organize foundation + Filter

## Goal
Establish the **organize layer** over the existing Tasks store and ship the first consumer, **Filter (All / Active / Completed)** on Home (F-023/F-024/F-025, all P0). This anchors ORG's Tier-1 mechanic: a **`taskQueryStore`** (Zustand — the active filter + sort **persisted to MMKV** via the guarded-preference pattern; search text in-memory, resets on launch) and a pure **`selectVisibleTasks(tasks, query)` derived selector** that runs the composable **search → filter → sort** pipeline. Home's list stops rendering `state.tasks` raw and instead renders the derived, filtered result. ORG-002 (search) and ORG-003 (sort) plug into the SAME pipeline + store — this task builds the spine + the filter slice; search is a pass-through and sort defaults to creation-date-newest until those tasks land.

> **Architecture decision (resolved at /module ORG):** ORG is **not** a new `features/organize` slice — the query store, the selector, and the Home wiring all live inside **`features/tasks`** (they read the same `useTaskStore`; a separate feature reading `features/tasks`' store would be a `features→features` boundary violation). The "ORG module" is an orchestration grouping, not a separate feature folder.

## Functional requirements
- **FR1 — `taskQueryStore`** (`features/tasks/store/taskQueryStore.ts`): a Zustand store holding the organize UI-state:
  - `filter: 'all' | 'active' | 'completed'` (default `'all'`) and `sort: TaskSortKey` (default `'created-desc'`; define the union now — `'created-desc'` used here, `'due'|'alpha'|'updated'` fully wired by ORG-003) — **persisted together as ONE `{filter,sort}` envelope** via the **typed storage service** (`createPersistedValue(StorageKeys.taskQuery, taskQueryPrefsSchema, {filter:'all',sort:'created-desc'})` — patterns-registry.md rows 18/19), **NOT** two raw MMKV keys and **NOT** the `themeStore` raw-key shape (grandfathered FND-era exception, not a template for new persisted values — registry row 17). `setFilter`/`setSort` each persist the full envelope (never a partial write), then update state.
  - `search: string` (default `''`) — **in-memory only, NOT persisted** (resets each launch, per the resolved decision). `setSearch` is plain state.
  - Guarded reads: a corrupt/absent/unparseable persisted envelope falls back to the default (never crashes) — the typed storage service's total-read discipline (F-038), inherited for free via `createPersistedValue`.
- **FR2 — `selectVisibleTasks(tasks, query)`** (`features/tasks/lib/selectVisibleTasks.ts`): a **pure** function running the composable pipeline **search → filter → sort** and returning a new array (never mutates the input `tasks` — the store array is the persistence-order source of truth, coherence invariant). This task implements: **filter** (all → passthrough; active → `status==='active'`; completed → `status==='completed'`) and a **default sort** (`created-desc` — newest `createdAt` first). **Search is a pass-through here** (empty `search` → no-op; ORG-002 implements the title/description match). **Sort beyond `created-desc` is ORG-003.** Structure the pipeline so ORG-002 slots the search predicate + ORG-003 slots the sort comparator without re-architecting.
- **FR3 — Filter control on Home (F-023/024/025):** render a `SegmentedControl` (All / Active / Completed) at the top of Home, bound to `taskQueryStore.filter`/`setFilter`. Changing it re-derives the list instantly (compose-ready). ≥48dp, labeled, both themes (the primitive already satisfies this).
- **FR4 — Home renders the derived list:** replace Home's `data={tasks}` with `data={selectVisibleTasks(tasks, query)}` (memoize the selector call — `useMemo` over `tasks` + `filter` + `sort` + `search`). The list stays the virtualized `FlatList` + memoized `TaskListItem` (do NOT regress TSK-001's memoization/perf). The FAB, pull-to-refresh, greeting, row nav all stay.
- **FR5 — Empty states (composition-aware):** distinguish (a) **no tasks at all** → the existing "No tasks yet" `EmptyState` (TSK-001, unchanged); (b) **tasks exist but none match the active filter** (e.g. filter=Completed, none completed) → an `EmptyState` with filter-appropriate copy (e.g. "No completed tasks"). Both reuse the `EmptyState` primitive (a fork is `[blocking]`). (The no-**search**-results state F-031 is ORG-002.)
- **FR6 — Persistence round-trips:** set filter=Active + (later) a sort, background/kill/relaunch → the store rehydrates filter+sort from MMKV; search is empty on relaunch. **OQ-8 invariant:** toggling a task's status must NOT reorder the list (the sort is stable over the persistence order; a completed task stays in place under All) — do not re-sort on toggle.

## Non-functional requirements
- **Accessibility:** the filter `SegmentedControl` labeled (`accessibilityRole="tablist"`/`"tab"` from the primitive); ≥48dp; both themes; fontScale. Maestro-anchorable on the visible segment text ("All"/"Active"/"Completed").
- **Correctness:** `selectVisibleTasks` is pure (no store mutation, no `updatedAt` recompute); the store's `tasks` array order is never mutated by ORG (sort is a view concern).
- **Performance:** the derived selector is memoized; large lists don't re-run the pipeline on unrelated renders; `TaskListItem` stays `React.memo` (no whole-list re-render on filter change beyond the necessary data swap).
