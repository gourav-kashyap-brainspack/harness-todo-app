# ORG-003 — Sort (due · created · alpha · updated)

## Goal
Add **sort** to the task list: by **due date** (F-026), **creation date** (F-027), **alphabetically** (F-028), and **recently updated** (F-029), surfaced via an **`ActionSheet` menu** (reusing the primitive) on Home. The chosen sort **persists to MMKV** (established in ORG-001's `taskQueryStore`, default `created-desc` = newest first). Sort implements the **sort stage** of `selectVisibleTasks` and **composes** with the active search + filter.

## Context links
- Source feature(s): F-026 (Sort by Due Date), F-027 (Sort by Creation Date), F-028 (Sort Alphabetically), F-029 (Sort by Recently Updated).
- Depends on: **ORG-001** — the `taskQueryStore` (`sort: TaskSortKey`/`setSort`, already MMKV-persisted with default `created-desc`) + `selectVisibleTasks` (the pipeline with the sort comparator slot).
- Reuse: **`ActionSheet`** (`@/components/ui` — the app's menu/confirm primitive; `title?` + option `icon?` available; PRO-003/TSK-004) for the sort-option menu · `date-fns`/native `Date` compare · `IconButton`/`Button` for the sort trigger.

## Functional requirements
- **FR1 — `TaskSortKey` (finalize the union):** `'created-desc' | 'due' | 'alpha' | 'updated'` (ORG-001 declared it; this task wires all values). Recommended semantics: `created-desc` = newest `createdAt` first (default); `due` = soonest `dueDate` first; `alpha` = title A→Z; `updated` = most-recent `updatedAt` first. (Creation-date F-027 is the default `created-desc`; if a distinct oldest-first is ever wanted it's a future key — MVP: creation = newest-first default.)
- **FR2 — Sort menu (F-026–029):** a sort trigger in Home's organize header (reserved slot) opens an **`ActionSheet`** (`title="Sort by"`) listing: **Due date · Creation date · Alphabetical · Recently updated**. Selecting one calls `taskQueryStore.setSort(key)` (persists) → the list re-derives instantly. Indicate the active sort (e.g. a check `icon` on the current option). Reuse `ActionSheet` — a bespoke menu `Modal` is `[blocking]`.
- **FR3 — Sort comparators in `selectVisibleTasks` (the sort stage):** implement a pure, **stable** comparator per key, applied AFTER search+filter:
  - `due` (F-026): ascending by `dueDate`; **tasks with no `dueDate` sort LAST** (dueDate is optional) — stable among themselves.
  - `created-desc` (F-027): descending by `createdAt` (newest first) — the default.
  - `alpha` (F-028): by `title`, **case-insensitive** (`localeCompare`), A→Z.
  - `updated` (F-029): descending by `updatedAt` (most recently changed first).
  - Never mutate the store's `tasks` array — sort a copy (the store order is the persistence source of truth; coherence invariant).
- **FR4 — Composition + OQ-8:** sort composes with search + filter (sort the search∩filter result). **Critical OQ-8 invariant:** a **status toggle must NOT reorder the list** — toggling complete/pending changes `updatedAt`, so under `sort='updated'` a toggled task legitimately moves, but under the DEFAULT and other sorts the row stays in place. Ensure the list only re-sorts on an explicit sort change or a data change that the active sort key depends on — do not force a re-sort on every toggle. (The registry/`TaskListItem` note: the parent list must never re-sort purely because of a toggle under a stable/creation sort.)
- **FR5 — Persistence:** the chosen sort persists across relaunch (ORG-001's MMKV key); default `created-desc` on first run / corrupt read.

- **Performance:** sort a memoized copy; O(n log n) over the local list; `TaskListItem` memoization preserved.
