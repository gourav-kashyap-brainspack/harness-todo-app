# TSK-005 — Due date (assign + remove)

## Goal
Add an optional **due date + time** to a task (F-016) and let the user **remove** it (F-017), by extending the shared `TaskForm` with a date+time picker (`@react-native-community/datetimepicker`, resolved decision). The value is persisted as a full ISO-8601 datetime string on `Task.dueDate` (STG gap b — serialize via `.toISOString()`).

## Context links
- Source feature(s): F-016 (Assign Due Date), F-017 (Remove Due Date)
- Depends on: TSK-002 (the `TaskForm` this extends) — appears in both create + edit forms once added.
- STG seam: `Task.dueDate?: string` (`z.string().datetime()` optional — `core/types/task.ts`); persisted via `taskRepository` through the store. STG gap b: `dueDate` MUST be a full ISO-8601 datetime (UTC `Z`) — `.toISOString()`; a bare `YYYY-MM-DD` fails Zod and the write throws.
- Reuse: `Button`/`FormField` treatment, `date-fns` for display formatting, tokens.

## Functional requirements
- **FR1 — Install & configure `@react-native-community/datetimepicker`** (resolve current stable via `npm view`; RN-0.75-compatible; `npm install --legacy-peer-deps`). Native autolink (Android) + `pod install` (iOS). Record the resolved version (librarian). No special permissions (it's a picker dialog, not camera/photos).
- **FR2 — Due-date field in `TaskForm` (F-016):** a control that opens the native date **and** time picker (date + time per the resolved decision). On pick → set `dueDate` in the form as a JS Date, serialized to a **full ISO string via `.toISOString()`** on submit (gap b). Show the selected due date+time human-readably (via `date-fns`) when set. Available in BOTH create (TSK-002) and edit (TSK-003) since it's the shared form.
- **FR3 — Remove due date (F-017):** when a due date is set, a **Clear/Remove** affordance sets `dueDate` to `undefined` → the task persists without a due date (the field is optional). The picker returns to the "no due date" state.
- **FR4 — Optional + validated:** `dueDate` is optional; when present it's a valid ISO datetime (Zod-validated at the form boundary — gap f); when absent, omit it. No due date is a valid task.
- **FR5 — Display consistency:** the due date shows on the list row (TSK-001) + detail (TSK-003) when set — TSK-005 supplies the formatting/util so those surfaces render it (or confirms they already read `task.dueDate`). Overdue styling is optional/not required for MVP.

## Non-functional requirements
- **Accessibility:** the due-date control + clear affordance labeled (`accessibilityLabel` "Set due date"/"Remove due date"); the picker is the native OS dialog (accessible by default); ≥48dp trigger; fontScale.
- **Correctness:** always serialize with `.toISOString()` (gap b); never persist a bare date.
