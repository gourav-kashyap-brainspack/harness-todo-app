# TSK-003 — Task detail + edit

## Goal
Let the user open a task's full details (F-009 — including creation F-018 and last-updated F-019 dates) by tapping a list row (F-040), and edit it (F-010) from the detail screen (F-041), reusing the shared `TaskForm`. Editing writes the **full business-field set** back via `updateTask` (STG gap a: `upsertTask` is a wholesale replace).

## Context links
- Source feature(s): F-009 (View Task Details), F-010 (Edit Task), F-018 (Display Creation Date), F-019 (Display Last Updated Date), F-040 (Navigate to Task Details), F-041 (Navigate to Edit Task)
- Depends on: TSK-002 (`TaskForm`) + TSK-001 (`taskStore` + list rows).
- STG/FND seams: `taskStore` (`updateTask`, reads `tasks`), `Task` type, the `TaskDetail: {taskId}` + `EditTask: {taskId}` typed routes (`RootStackParamList`, already defined FND-003), `Screen`, `useAppRoute`/`useAppNavigation`, `date-fns` (installed dormant — usable for formatting dates, it's a local util not the dormant network stack).

## Functional requirements
- **FR1 — Navigate to detail (F-040):** tapping a Home list row (TSK-001) navigates to `TaskDetail` with the task's `id` (typed `{taskId: string}` — matches STG gap d, id is a uuid string). Wire the row press.
- **FR2 — Task Detail screen** (`src/features/tasks/screens/TaskDetailScreen`, replacing the FND placeholder): reads the task from the store by `route.params.taskId` (single source — coherence check 3; if not found, a safe empty/back). Displays: **title**, **description**, **status** (active/completed with the same treatment as the list), **due date** (if set — added visible once TSK-005 lands; show "No due date" otherwise), **created** (F-018) + **last updated** (F-019) timestamps formatted human-readably (via `date-fns`). An **Edit** affordance → navigates to `EditTask` (F-041). (Delete/complete/duplicate actions are TSK-004 — leave room.)
- **FR3 — Navigate to edit (F-041):** the Edit affordance navigates to `EditTask` with `{taskId}`.
- **FR4 — Edit Task screen** (`src/features/tasks/screens/EditTaskScreen`, replacing the FND placeholder): reads the task by `taskId`, renders `TaskForm` **seeded with the task's current values** (`defaultValues` from the store task — like PRO-002's `reset(profile)` divergence). On valid submit → `taskStore.updateTask({id, ...allFields})` → `taskRepository.upsertTask` (keeps `id`/`createdAt`, bumps `updatedAt` once — coherence check 2). **Submit the FULL business-field set** (title, description, status, dueDate) every save — STG gap a (`upsertTask` wholesale-replaces; a partial submit blanks omitted fields). Cancel discards, back to detail.
- **FR5 — Boundary validation (STG gap f):** the edit form validates via the same `zodResolver` (title required); invalid never reaches `upsertTask`.
- **FR6 — Live detail:** the detail screen reflects store changes (after an edit, the detail shows updated values + a bumped `updatedAt`) — reads from the store, no stale copy.

## Non-functional requirements
- **Accessibility:** detail fields readable (contrast both themes); dates labeled; Edit affordance labeled; edit form errors announced; ≥48dp; fontScale.
- **Correctness:** `updatedAt` bumped once in the repo (never recomputed per screen — coherence check 2); detail reads the single store task (no duplicate state — check 3).
