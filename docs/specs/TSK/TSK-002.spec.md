# TSK-002 — Create task

## Goal
Let the user create a task (F-007) via the **Add Task screen** and a **shared `TaskForm`** built on the established RHF+Zod form pattern (PRO's anchor) — title required (F-034), with a duplicate-submit guard (F-035). The `TaskForm` is reused by TSK-003 (edit) and extended by TSK-005 (due date), so it must be clean + reusable.

## Context links
- Source feature(s): F-007 (Create Task), F-034 (Require Task Title), F-035 (Prevent Duplicate Submission)
- Depends on: TSK-001 (the `taskStore` + its `addTask` action).
- Reuse (PRO anchor): the **RHF + Zod form pattern** (`zodResolver` + `Controller` + `FormField` + `Button`) — see `patterns-registry.md`; `FormField`/`Button` from `@/components/ui`.
- STG seam: `taskRepository.upsertTask` (via the store's `addTask`); `taskSchema` fields (`core/types/task.ts`).
- FND seam: the `AddTask` route + placeholder (`screens.tsx`), `Screen`, typed nav (pushed screen).

## Functional requirements
- **FR1 — `TaskForm`** (`src/features/tasks/components/TaskForm.tsx`) — the shared, reusable task form (create + edit both use it): fields **Title** (required, F-034) + **Description** (optional, multiline). Built with `react-hook-form` + `@hookform/resolvers/zod`, resolver = a Zod schema derived from `taskSchema` for the editable business fields (`title` required non-empty; `description` optional). Inline field errors via `FormField` (the danger treatment). `mode: 'onBlur'`. Takes `defaultValues` (empty for create; seeded for edit — TSK-003) + an `onSubmit(values)` callback. **The due-date field is added by TSK-005** — leave the form structured so it slots in.
- **FR2 — Add Task screen** (`src/features/tasks/screens/AddTaskScreen`, replacing the FND placeholder on the `AddTask` route): renders `TaskForm` (empty) + a primary submit (`Button`, "Add"/"Create"). On valid submit → `taskStore.addTask(values)` (→ `taskRepository.upsertTask` with a fresh id + `createdAt`/`updatedAt` + `status:'active'`) → navigate back to Home (the new task appears in the list). Cancel/back discards.
- **FR3 — Require title (F-034) + boundary validation (STG gap f):** the Zod resolver enforces a non-empty trimmed title; **invalid input never reaches `upsertTask`** (which throws on invalid) — `handleSubmit` only calls `onSubmit` after validation passes. Empty title → inline error, no create.
- **FR4 — Prevent duplicate submission (F-035):** guard against a double-tap creating two tasks — disable/guard the submit while submitting (the `Button` loading state + an `isSubmitting`/`hasSubmittedRef` guard, per the PRO form pattern — include the ref guard here since a create side-effect is NOT idempotent). One tap = one task.
- **FR5 — New-task shape:** `addTask` produces `status:'active'`, a uuid `id` (via `newId` in `taskRepository`), `createdAt`/`updatedAt` = now (ISO). Title trimmed. Description optional.

## Non-functional requirements
- **Accessibility:** labeled inputs, announced errors (F-034), submit labeled, keyboard handling (the keyboard-aware `Screen`), ≥48dp, fontScale, both themes.
- **Reliability:** validation prevents invalid persistence; duplicate-submit guard prevents accidental double-create (F-035).
