| Typed storage service (the ONE persistence path) | All domain persistence goes through `core/services/storage.ts`'s `getItem<T>(key,schema,fallback)`/`setItem`/`removeItem`/`hasItem` — no feature/domain code imports `react-native-mmkv` directly (code-reviewer blocks it). Keys are declared once in the `StorageKeys` registry (single source of truth, prevents key-string drift). Two hard-won correctness rules for anyone extending this: **(a)** the "can't migrate this version" sentinel MUST be a `Symbol` (`UNMIGRATABLE`), never `null` — `null` is a legitimate persisted `data` value (e.g. a nullable Zod schema), so reusing it as a corrupt-marker would wrongly discard real data; **(b)** the corrupt/thrown-read path logs `error.name` only, never `String(error)`/`error.message`/the raw stored string — a `JSON.parse` error message can echo a fragment of the corrupt blob, which may contain PII once STG-002+ payloads (profile name/email) land | `mobile/src/core/services/storage.ts:getItem,setItem,removeItem,hasItem,StorageKeys,migrate` + `mobile/src/core/types/storage.ts:StorageEnvelope` | STG-001 | — |

| Repository pattern (total reads, validating writes, pure-transform mutations) | A repository's read is **total** (absent/corrupt → the caller's safe default via `getItem` — `null` for a singleton, `[]` for a collection — never throws); its write Zod-validates before persisting and throws on mismatch (a caller bug, e.g. an unvalidated form value, not corrupt storage — deliberately not swallowed). A collection repository adds `upsertTask(input)`/`removeTask(id)` as **pure transforms**: read the full collection, compute the next array, persist it, return it — callers never touch MMKV or hand-diff the array. `upsertTask` on an existing id is a **wholesale field replace**, not a partial patch — any edit-form caller must submit the full set of business fields, not just the changed ones | `mobile/src/core/services/taskRepository.ts:upsertTask,removeTask` + `mobile/src/core/services/profileRepository.ts:getProfile,saveProfile,clearProfile` | STG-002 | — |
