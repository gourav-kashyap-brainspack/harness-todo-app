# ADR 0038 — Project Profile · lean CI · `/setup`-with-prune · time/telemetry/OQ batch

- **Status:** accepted (2026-07-04)
- **Context:** A harness audit found recurring gaps: CI often placed under `mobile/.github/` never ran (GitHub reads only the repo root); release hardening was prose with no gate; capability variance (platforms, which gates run, on/off) was hardcoded rather than switched; and there was no time tracking, live telemetry, or upfront Open-Question batching for autonomous runs. Guiding directives: **CI should be lean by default** (no E2E, no native build, no test-suite jobs — those are local gates), **release hardening is asked-at-configuration, not silently enforced**, **the harness must not bloat token usage during execution**, and **after configuration, machinery a project doesn't use is pruned** so it carries only the harness it needs.

## Decisions

1. **Project Profile** (`harness.config.md`) — the Design-Profile pattern generalized to every capability: one keyed switch table (platforms · ciTier · unitGate · buildGate · e2eGate · visualParity · releaseHardening · offlineTier · perfBudget · intakeMode · timeTracking · telemetryDashboard), resolved **once** by `/setup`, consumed by gate-runner (active gates) / orchestrator (Module-DoD composition, CI expectations) / CI. This is the umbrella mechanism; it also carries `intakeMode` (`/require` is input-gated — built only when a project picks `incremental`).
2. **Lean CI** (`ciTier: lean`, default): the ONLY workflow is repo-root `.github/workflows/ci.yml` — typecheck · lint · promoted grep guards · traceability · Layer-0 token bridge. **No native build, no unit suite, no E2E, no device/visual jobs.** The unit suite + native build stay **local** gates (gate-runner, unchanged in strictness); CI-green means "static tier green", never "fully gated". Amends the CI-facing halves of ADR-0018/0022/0033 (native-override note: the local full-build is the native protection — CI can't catch it). `standard` adds the unit job, `full` adds native build; never E2E (ADR-0012).
3. **Release hardening = asked, default `advisory`** (never silently enforced): pin values / ProGuard / Hermes / release keystore / attestation / plist keys are a release-lane **checklist**, not a gate. `/setup` (and any `development → main` request) asks whether to flip `releaseHardening: enforced`, which is when `check-release-hardening.sh` gets built and wired as a blocking local release gate. Not built until then — no dead machinery.
4. **`/setup` preflight with a mandatory PRUNE pass** (implements the setup-preflight decision, ADR-0036): env checks → batched Project Profile interrogation → write the table → **remove/disable the machinery behind every OFF switch** (map in the skill), logging each cut to `harness-debt.md` (reversible via git/template). Guardrails (main-guard, run-ledger, CHECKPOINT, output-bounding, Context Manifest) are never prunable. Marker: `docs/graph/SETUP-COMPLETE.md`. `/setup` runs **before `/scope`** on every new project from this template.
5. **Time tracking** (Project Profile `timeTracking`): `estimate`/`startedAt`/`doneAt` on tasks in `modules.json`; orchestrator stamps at in-progress/done; ETA table at batch boundaries + one `## ETA` line in CHECKPOINT. No new files or agents.
6. **Telemetry dashboard** (`telemetryDashboard`): `telemetry-report.mjs --dashboard` overwrites `docs/graph/telemetry/DASHBOARD.md` (skips the ccusage/network call + trend append — cheap), invoked by the orchestrator at the same safe moments as CHECKPOINT writes. Fail-soft — a telemetry error never blocks a build.
7. **Batched OQs**: architect consolidates all of a module's Open Questions into ONE AskUserQuestion session at `/module` exit; orchestrator runs an OQ pre-flight sweep before any autonomous batch walk, so a walk never stalls mid-run.
8. **Lean Execution rules** (`harness.config.md`) — the token-efficiency contract consolidated: mandatory output-bounding, module-edge-only graphify rebuilds, manifest-key context loading (no doc bodies pasted into subagent prompts), overwrite-not-append run-state, scoped gate reruns, an always-loaded-prose budget (ADR-0028 bias), and prune-at-setup.

## Consequences
- CI can no longer catch a local-green/CI-red native or unit regression — accepted trade; the gate of record is local and `MERGE_WAIT_FOR_CI`'s value shrinks to the static tier. Flip `ciTier` via `/setup` if this bites.
- A capability switched off leaves no machinery behind — re-enabling is a `/setup` re-run + git/template restore, recorded in `harness-debt.md`.
- The root `ci.yml` references `mobile/`-scoped npm scripts and `scripts/check-*.sh`. A `detect` job self-guards on `mobile/package.json`: on the bare template the app jobs **skip green** (never red), and they light up automatically once a project scaffolds the `mobile/` app.
